# Publication policy

Use an explicit file allowlist for tracked release files and a separate static export. Before release, inspect the staged tree, tracked history and generated export against these rules, including lower-frequency aggregate cells and bundle contents. Retain the local audit with hashes.

- Eligible source consists of implementation, lockfiles, reviewed documentation, explicitly synthetic fixtures, and reviewed aggregate output with lineage.
- Keep .project, agent instructions, local data, identifiers, logs, run manifests with private data, checkpoints and trained models out of Git and static export.
- Public tables have no claim-level records, procedure identifiers or named providers. Aggregate results require documented cohort definitions and disclosure review.
- Score and planning demos in an exported browser build can use precomputed aggregates and fictional scenarios. Live model access is local.
- External publication and hosting require separate target authorization. Release files must use only static services with verified zero additional spend.
